# 四种版式的写法与 HTML

## 版式一：讲解节

讲解节是文章的细胞。它的价值全在**顺序**上：先给读者一个“需要”，再给定义。

### 结构

```html
<h3>3.2 关系的码：为什么一个表需要好几种码</h3>

<p class="lead">上一节讲了关系是一张二维表。但表里哪一列能唯一认出一个人？这是本节要解决的。</p>

<div class="def">
  <div class="def-h">候选码 <span class="tag">必背</span></div>
  <div class="def-b">
    <p class="std">若关系中的某一属性组的值能唯一地标识一个元组，而其真子集不能，则称该属性组为候选码。</p>
    <p class="plain">白话：能唯一认出这一行、且没有多余列的最小组合。</p>
    <p class="pt">考点：常问"候选码有几个"；"最小"两个字不能丢。</p>
  </div>
</div>

<p>最小例子：学生表 (Sno, Sname, Sdept)。Sno 能唯一认人，(Sno, Sname) 也能，但 Sname 多余，所以只有 Sno 是候选码。</p>

<table class="compact"><!-- 辨析表 --></table>

<div class="box tip"><span class="bt">一句话记住</span>候选码是"能当主码的"，主码是"已经当了的"，外码是"抄别人的"。</div>
```

### 节标题的写法

标题要包含**这个概念存在的原因**，不只是名字。

- 差：`3.2 关系的码`
- 好：`3.2 关系的码：为什么一个表需要好几种码`

读者扫目录时，看到的是问题，才会想读。

### 承上启下的一句话

每个讲解节的第一段（`p.lead`）必须做两件事：**提上一节、提本节的问题**。

```
上一节讲了 X。但 X 解决不了 Y，这是本节要处理的。
```

这一句是“文章”和“手册”的分水岭。没有它，每节都是孤岛，读者读到第四节就丢了。

### 定义卡（嵌在讲解节内）

```html
<div class="def">
  <div class="def-h">术语名 <span class="tag">必背</span></div>
  <div class="def-b">
    <p class="std">教材或考卷的定义原文，一字不改，不合并句子。</p>
    <p class="plain">白话：一句大白话或一个比喻。</p>
    <p class="pt">考点：常问"……"→ 答……。</p>
  </div>
</div>
```

三个 `p` 的类名固定：`std` 原话、`plain` 白话、`pt` 考点。不要加第四层。

标签 `tag` 只用三种：`必背`、`辨析`、`易错`。

**定义卡的纪律**：

- 定义卡嵌在讲解里，**不单独成“定义汇总”一章**。抽出来集中放会造成同一内容写两遍
- 并列的术语（如 数据 / 数据库 / DBMS / DBS）做成**一张对照卡**，不拆成四张
- 原话不分句合并。教材分两句写的就写两句，评分点是关键词
- 白话只写一句。能比喻就比喻，写不出比喻就写“三个关键词：A / B / C”

### 辨析表

第三列固定写“差在哪”，不要写“特点”。

```html
<table class="compact">
  <thead><tr><th>叫法</th><th>它是什么</th><th>和相邻的区别</th></tr></thead>
  <tbody>
    <tr><td>候选码</td><td>能唯一标识且最小的属性组</td><td>—</td></tr>
    <tr><td>主码</td><td>从候选码里挑出来用的那一个</td><td>候选码可有多个，主码只有一个</td></tr>
  </tbody>
</table>
```

## 版式二：例题双栏

### 为什么只有这一种

| 写法 | 读者的使用方式 | 问题 |
|---|---|---|
| 语法模板 + 参数说明表（两分开） | 先背模板，再回查参数 | 信息要来回跳，模板脱离题目没意义 |
| 代码 + 下方箭头注释（上下分块） | 眼睛上下扫，找对应 | 找不到哪句注释对应哪一行 |
| **左栏代码 / 右栏解释（同一行）** | 一眼横向读完 | 无 |

第三种之所以对：代码行和解释行在**同一条水平线**上，视线不跳跃。右栏还顺手完成“通用写法 → 这里填了什么”的换算，这正是做题时脑子里的动作。

**不允许出现另外两种格式**，哪怕作为“补充说明”也不行。

### 结构

```html
<div class="ex">
  <div class="ex-h"><span class="lb">例 1</span><span>用考卷的问法写题目。</span></div>
  <table class="ct">
    <tr>
      <td class="c1"><span class="k">SELECT</span> <span class="req">*</span></td>
      <td class="c2"><b>回答"取哪些列"</b>。<b>*</b> 就是全部列，题目说"详细记录"一律用它</td>
    </tr>
    <tr>
      <td class="c1"><span class="k">FROM</span>   <span class="req">表名</span>;</td>
      <td class="c2"><b>回答"从哪张表取"</b>：FROM 表名 → 这里表名填实际那张</td>
    </tr>
    <tr class="blank"><td class="c1"></td><td class="c2"></td></tr>
    <tr>
      <td class="c1"><span class="k">WHERE</span>  <span class="req">条件</span></td>
      <td class="c2">题目没有条件就别硬加，多写反而扣分</td>
    </tr>
  </table>
  <div class="ex-note">
    <p>只放坑 / 变体 / 得分点，不重复右栏说过的话。</p>
  </div>
</div>
```

`<span class="req">` 标“这里该填的东西”，视觉上是浅底加下划线。

### 右栏三件事

1. **说这一行在干什么** —— “建表的固定骨架”
2. **做换算** —— `CREATE TABLE 表名` → 这里表名就是 Student
3. **提示顺序或易错** —— “顺序不能反”“逗号不是结尾符”

三种典型句式：

```
<b>CREATE TABLE ＋ 表名 ＋ 括号</b>：…这里表名就是 <b>Student</b>
一行三样：<b>列名</b> X → <b>类型</b> Y → <b>约束</b> Z
这里是"唯一"这个要求的落点，只写 UNIQUE 会漏"非空"这一分
```

**长度纪律**：右栏每行 ≤ 35 个汉字。超了说明在写段落，该拆到 `ex-note`。

**不要做**：

- 不要用“这段代码的作用是……”开场
- 不要把两行代码塞进一个单元格 —— 一行代码对一行解释，这是这种格式的全部意义
- 不要在右栏重复左栏已有的代码

### 行数

- 每例 4–12 行。超过 12 行拆成两例
- 空行用 `<tr class="blank">` 保留代码的段落感
- 缩进必须保留（`white-space:pre`），HTML 里行首空格原样打进去

## 版式三：汇总表（通用知识）

约束、数据类型、运算符这类通用知识，单独成表，不散落在例题里。

判据：**能被三道以上例题用到的知识**，就该有一张表。

```html
<table>
  <thead><tr><th style="width:20%">约束</th><th style="width:34%">管什么</th><th>写错会怎样</th></tr></thead>
  <tbody>
    <tr><td>PRIMARY KEY</td><td>不许重复、不许空，一表一个</td><td>多属性主码挂到某一列后面 → 语法错</td></tr>
    <tr><td>UNIQUE</td><td>不许重复，允许一个空值</td><td>以为等于主码 → 语义题丢分</td></tr>
  </tbody>
</table>
```

三列起步，第三列写**后果**，不写“备注”。

## 版式四：速记清单

```html
<div class="nums">
  <span><b>3</b> 级模式</span><span><b>2</b> 级映像</span><span><b>8</b> 种运算</span>
</div>
```

一行 6–8 个，每个不超过 8 个字。

```html
<ul class="check">
  <li>能不能默写出三级模式的定义</li>
  <li>能不能分清主码和候选码</li>
</ul>
```

## 全文语言规范

**用命令句，不用建议句。**
- 差：建议先复习定义部分
- 好：先抄定义，一遍过，不要停

**写具体问法，不写抽象要求。**
- 差：重点掌握完整性约束
- 好：常考“删父表记录子表怎么办”→ 三种答案：拒绝 / 级联 / 置空

**不交代写作意图。**
删掉所有“本节将介绍…”“下面我们来看…”“通过以上分析可以得出…”。直接给内容。

**不写鼓励话。**
“加油”“相信你”“别紧张”一律不要。

**术语首现给全称。**
“数据库管理系统（DBMS）”首现，之后写 DBMS。

**对比一律用表格。**
三种方案的优缺点写成三行表，不要三段话。

**例子要能一眼验算。**
用 3 行的表，不要 10 行的表。例子是用来验证定义的，不是用来展示现实复杂度的。

- [ ] 有没有整节只有定义没有“为什么”
- [ ] 有没有讲解节的第一段没有承上启下
- [ ] 有没有出现单独的“语法模板”块
- [ ] 有没有出现上下分块的箭头注释
- [ ] 有没有右栏单元格超过 35 字
- [ ] 有没有定义卡只有一层
- [ ] 有没有把并列术语拆成多张卡
- [ ] 有没有一节超过 2 页
- [ ] 有没有“本节将介绍”这类句子
- [ ] 有没有“1. 2. 3.”排到底的条目清单
